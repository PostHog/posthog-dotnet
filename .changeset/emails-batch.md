"PostHog": minor

Send the same transactional email to up to 100 recipients in one request with `Emails.BatchAsync`, one email each, from a template with `TemplateData` per recipient (`SendTemplateBatchOptions`) or from content in your code (`SendCodeBatchOptions`). More than 100 recipients throws `ArgumentException` before anything is sent. The client checks only the recipient count and throws PostHog's refusals with PostHog's own fix: HTTP 413 with `content_too_large` means the batch is too large as a whole, so split the recipients into smaller batches, and HTTP 400 with `content_too_large` means the shared content or template data is too large, which splitting doesn't change. The client waits up to 45 seconds for the answer, gives each recipient an idempotency key that every retry within the call reuses, and returns a result per recipient in input order: `queued`, `failed` or `unconfirmed`. PostHog replays a key for 24 hours, so a batch sent again within that window with the same `IdempotencyKey` for each recipient queues no second email for a recipient it already accepted. Keys the client makes cover retries within one call only, so pass keys you store when a batch may run twice. An `unconfirmed` recipient may still get the email, also when a retry after a lost answer is refused: send it again with the same `IdempotencyKey` within 24 hours of the key's first use, so it goes out once. A request that fails as a whole throws `EmailBatchException`, an `EmailException` whose `Results` hold every recipient. `EmailException` is no longer sealed.

`IPostHogEmails` gains `BatchAsync`. Code that calls the client is unaffected, but a class of your own that implements `IPostHogEmails`, such as a test fake, must add `BatchAsync` to compile against this version.
