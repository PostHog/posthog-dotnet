`SendCodeEmailOptions.Category` sends an email from code in a message category that you define in code with a `MessageCategory`: its `Key`, `Type` (`MessageCategoryType.Marketing` or `Transactional`), `Name` and an optional `Description`. Requires a PostHog server with code-send category support (requests that reach the send endpoint on older servers fail with an HTTP 400 unknown-field error naming the first unknown field the server finds, which can be another newer field such as `bcc` rather than `category`, while a send with `Attachments` to a server without the upload route stops at HTTP 404 `not_found` on `attachments` before submitting the email body). On a compatible server, `MessageCategory.Transactional` works even when code-send categories are disabled for the project; enabling code-send categories for the project gates named `MessageCategory` objects (otherwise PostHog refuses them with `categories_not_enabled`) and template-category inheritance when `Category` is omitted. When `TemplateKey` resolves to no saved template, PostHog creates the category by its key (or restores an archived one) after checking that a marketing send carries the `{{ unsubscribe_url }}` placeholder and no copies and after sender selection succeeds, before delivery checks run. Whether the HTML has a clickable unsubscribe link (`unsubscribe_link_required`) is checked later at delivery, after the category exists, so a send refused there (or refused with `recipient_opted_out`) still establishes the category and retrying with fixed HTML and different metadata keeps the original `Name` and `Description`. On a verified sender, a marketing send with a new category and an attachment also creates or restores the category before `workflow_can_wait` (or `workflow_shape_not_supported`) comes back (before any opt-out check), whereas on the PostHog test sender `sandbox_fields_unsupported` returns before category resolution so no category is created or restored. PostHog uses `Name` and `Description` only at creation: a send never renames a category or changes its description, so change them later in PostHog. Both creating a new category and restoring an archived one count against the project's active-category limit (`too_many_categories`). When `TemplateKey` names a saved template, the send uses that template's transactional category without creating a category or restoring an archived one: leave `Category` out to send transactional email with no category, as before, or to follow the saved template's transactional category when code-send categories are enabled for the project; passing an explicit `Category` must match that template's category or PostHog refuses the send with `category_mismatch`. Pass `MessageCategory.Transactional` directly (rather than constructing `new MessageCategory { Key = "transactional", ... }`) to send transactional email with no category, which PostHog refuses with `category_mismatch` for a template in a category. With code-send categories enabled, when `TemplateKey` resolves to a saved template, PostHog refuses a sensitive template when `Sensitive` is `false` (`sensitive_template`) first, then refuses a saved push template with `template_not_sendable`; for a saved email template, PostHog checks whether it is enabled for transactional sends (`template_not_transactional` otherwise) before refusing an otherwise sendable email template in a marketing category with `marketing_template` or comparing categories. A marketing email from code honors the recipient's opt-outs (`recipient_opted_out`), needs a clickable `<a href="{{ unsubscribe_url }}">` link in its `Html` (or the `{{ unsubscribe_url }}` placeholder in its `Text` when it has no `Html`, else `unsubscribe_link_required`), takes no copies (`copies_not_allowed`), and cannot carry `Attachments` (`workflow_can_wait` on a verified sender because marketing sending limits can hold delivery, preceded by `workflow_shape_not_supported` if an existing code-send workflow has an unsupported shape, or `sandbox_fields_unsupported` on `attachments` when using the PostHog test sender; uploads run before PostHog refuses the send, and a terminal upload failure after retries or on a non-retryable error prevents the send).

```csharp
await posthog.Emails.SendAsync(new SendCodeEmailOptions
{
    To = "reader@example.com",
    TemplateKey = "monthly-news",
    Subject = "This month",
    Html = "<p>News</p><a href=\"{{ unsubscribe_url }}\">Unsubscribe</a>",
    Category = new MessageCategory
    {
        Key = "newsletter",
        Type = MessageCategoryType.Marketing,
        Name = "Newsletter",
        Description = "Monthly product news",
    },
});
```
