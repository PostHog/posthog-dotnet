`SendCodeEmailOptions` takes `Sensitive` and `Tracking`. Set `Sensitive = true` when the email carries login links, reset tokens or codes: PostHog then keeps its links unchanged unless `Tracking` turns clicks on, leaves its subject off engagement events, and keeps its content out of logs. Left unset, the email takes the setting of the template made in PostHog whose key matches `TemplateKey`, and is sensitive when no template matches. `Tracking` chooses what PostHog tracks for the email. Left unset, PostHog counts opens and captures engagement events, and tracks clicks only when the email isn't sensitive. `EmailTracking.All` (or `true`) turns on opens, clicks and engagement events, and `EmailTracking.None` (or `false`) turns them all off. `new EmailTracking { Clicks = true }` sets `Opens`, `Clicks` and `Engagement` one by one. `CaptureEngagement` is now obsolete in favor of `Tracking` with `Engagement`; it still works, but a send can't set both. The client now sends it only when you set it; PostHog already reads a missing value as on. The new fields need PostHog's API support, which is rolling out.
